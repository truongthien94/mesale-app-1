# Mesale Member Feature Inventory and Web-to-Native/API Matrix

Audit scope: active Laravel routes, member controllers, API v1 controllers, member/public Blade views and related services. Backup files (`*.pre-*`, `*.seo-backup-*`), generated views, `vendor/` and `node_modules/` are excluded. This document contains no production payloads, member data, credentials or tokens.

Status meanings:

- `Existing`: a mobile-safe Open API route is present in source; production availability still requires the Open API gate.
- `Partial`: an API exists but the web behavior, data shape or required platform coverage is incomplete.
- `Missing`: the feature is web-only or requires a new API contract.
- `Parity pending`: native implementation and screenshot evidence do not exist yet; Blade/CSS/assets are the visual baseline.

## Known web-only or contract gaps

1. Full home Page Builder blocks are server-rendered and not exposed as a stable JSON contract; `config` only carries basic brand/theme/flags/banners.
2. `UserDashboardController` exposes savings chart, created links and merged cashback history through web/AJAX routes; no equivalent Open API routes exist.
3. Blog read and UGC APIs are absent. The article view posts to `/blog/{id}/share`, but no corresponding route is declared in `routes/web.php`; resolve before native implementation.
4. Google native and Sign in with Apple OAuth exchange endpoints are absent.
5. Language/currency changes are session routes only; mobile preference read/write contract is absent.
6. Bot unlink has a web route only. Personal API keys must remain out of the app; add a narrowly scoped unlink endpoint only if the mobile product exposes this utility.
7. `config` includes Shopee/TikTok flags but no Lazada cashback fields; confirm Lazada feature/notice/price configuration before parity sign-off.
8. Local P0 code normalizes audited member money responses to integer VND; remaining/new fields and staging deployment must preserve the versioned rule.
9. Withdrawal creation and gift redemption now have a documented local idempotency contract; other retryable reward/account mutations and record retention remain open.
10. Production `GET /api/v1/openapi/config` was observed disabled (`503`); staging and production enablement/security review are mandatory blockers.

## Evidence and acceptance gates

- Every `Existing` row needs a contract test against staging, including `401`, `403` feature-off, `404`, `422` validation, `429` throttle, `5xx`, offline and retry behavior.
- Every native screen needs screenshot baselines derived from the corresponding active Blade view, on small iPhone, Pro Max, small Android and large Android, light/dark, keyboard/safe-area and font-scaling variants.
- Financial mutations (withdrawal, gift redemption, gift code, task claim, check-in and payment-account writes) require server-authoritative response assertions and idempotency tests before a milestone is marked complete.
- Blog/UGC surfaces require moderation/report/block/contact evidence for App Store and Google Play review.
