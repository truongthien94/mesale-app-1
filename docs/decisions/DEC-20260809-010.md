# DEC-20260809-010 - Round 3 store-compliance boundary

- Date: 2026-08-09
- Session: `SES-20260809-006`
- Status: Accepted for implementation groundwork; release approval not granted

## Decision

Keep the Laravel + Expo monorepo and implement credential-independent store-compliance groundwork in source. Native Google and Sign in with Apple clients exchange short-lived provider credentials with Laravel; the app stores only the Laravel session Bearer token. Public legal/deletion/support routes and deep-link association files are source artifacts, while provider IDs, signing fingerprints, support contacts, staging URLs, and store-console declarations remain owner inputs.

## Rationale

This preserves one business database and one user identity while avoiding production activation, fake credentials, direct database access, or a WebView-only submission. Store readiness requires evidence beyond source: staging, signed artifacts, physical devices, owner-approved legal text, and console declarations.

## Consequences

- `NOT READY` remains the App Store and Google Play verdict.
- AASA contains an Apple Team ID placeholder and Asset Links contains a release-certificate placeholder.
- Public support intentionally shows an owner-input state until a verified contact is configured.
- Provider feature flags and production Open API remain unchanged.
