# DEC-20260811-002 - Treat undeployed pending cashback as unavailable

- Session: `SES-20260811-003`
- Task: `TSK-MOB-018`
- Status: accepted

## Context

The requested Home summary needs a real pending cashback amount, but the production backend may be deployed separately from the mobile JavaScript update. Treating an absent response field as zero would present unverified financial information to the member.

## Decision

Laravel remains authoritative and adds integer VND `wallet.pending_cashback` to the existing authenticated `/account` response. During rolling deployment, the mobile parser maps only an omitted field to `null` and displays `--`; valid integer values display normally, while malformed or fractional values fail contract validation.

## Consequences

- Mobile can be published without falsely claiming the member has zero pending cashback.
- Backend deployment should precede release validation so the final UI shows the real amount.
- No calculation or financial mutation is duplicated in React Native.

## Reversal

After all supported backend versions guarantee the field, the compatibility branch may be removed in a separately tested API-version cleanup.
