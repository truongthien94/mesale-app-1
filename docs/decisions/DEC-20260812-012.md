# DEC-20260812-012 - Use native provider credentials with server-side Bearer exchange

- Date: 2026-08-12
- Session: `SES-20260812-016`
- Checkpoint: `CKP-20260812-022`
- Status: accepted and deployed for Google

## Decision

- Mobile uses native Google/Apple credentials and exchanges them through Laravel for a device-scoped Bearer token.
- Never reuse the website session/cookies, a personal Bot API key, a WebView login, or an email-only automatic account merge.
- Resolve Google accounts by verified provider `sub` and enforce a database UNIQUE invariant before enabling the endpoint.
- Keep provider endpoints default-off, redact credentials recursively before API logging, and enable only after migration and canary evidence pass.
- Keep Apple disabled until all server-only Apple credentials and signed iOS evidence are available.

## Rationale

- Provider subjects are stable identities; email alone is not a safe account-linking proof.
- Production uses MyISAM, so cache locks and application checks cannot replace a database UNIQUE constraint.
- Feature flags and scoped rollout allow immediate disablement without removing identity data or weakening the website login flow.
