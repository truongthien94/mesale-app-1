# DEC-20260815-002 - Reuse the Existing Password Screen

- Date: 2026-08-15
- Session: `SES-20260815-002`
- Checkpoint: `CKP-20260815-002`
- Status: accepted

## Decision

- Add a Security menu entry that navigates to the existing native password route.
- Keep the existing `account/password` API hook as the only password mutation implementation.
- Do not duplicate the password form inside the 2FA/email-OTP screen.

## Rationale

- One route and one mutation reduce validation drift and inconsistent security behavior.
- Laravel remains authoritative for current-password verification, hashing, and revoking other device tokens.
- The Security screen stays compact while still exposing the missing member action.
