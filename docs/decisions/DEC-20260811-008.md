# DEC-20260811-008 - Keep compact withdrawal inputs saved-account-derived

- Session: `SES-20260811-012`
- Task: `TSK-MOB-027`
- Status: accepted and published implementation decision
- Checkpoint: `CKP-20260811-018`

## Context

The approved web reference presents a compact withdrawal form with bank and account fields. Allowing those fields to become free-form mobile inputs would bypass saved payment-account controls, risk destination mismatches, and weaken the existing server-authoritative financial contract.

## Decision

- Follow the reference field order and compact visual density natively.
- Offer bank and wallet choices only when Laravel enables the corresponding method.
- Populate destination choices only from the authenticated member's saved payment accounts.
- Render account number and account-holder name as read-only values derived from the selected saved account.
- Preserve existing OTP, validation, stable idempotency, retry, auth, throttle, logging, and server-side balance/fee/minimum enforcement.
- Add bottom-tab-aware scroll padding rather than moving financial submission outside the screen's normal scroll and keyboard flow.

## Consequences

The mobile form gains the requested compact presentation without creating a second source of payment destination data or weakening financial controls. Physical-device, dark-mode, accessibility, signed-artifact, and store evidence remain required before release.
