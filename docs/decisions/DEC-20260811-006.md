# DEC-20260811-006 - Keep referral and avatar state server-authoritative behind nested Account navigation

- Session: `SES-20260811-010`
- Task: `TSK-MOB-025`
- Status: accepted local implementation decision
- Implementation source: `f9d87c9` (published directly to `origin/main`; CI run `31494516026` passed)

## Context

The Account hub had grown into a long list of detailed destinations, avatar editing required a safe native media flow, and referral-code entry needed a bounded onboarding window that could not be trusted to device time.

## Decision

- Keep one high-level row for each Account information, finance, notification, and settings section; open detailed actions on nested native screens.
- Use a React header driven by safe-area insets, with an accessible back action and a deterministic Account fallback when a deep link has no back history.
- Use the operating-system Photo Picker, bounded image resize, and authenticated Laravel endpoints for avatar upload and deletion. Do not request camera or broad media access.
- Make Laravel the sole authority for the 72-hour referral-code window. Do not backfill existing accounts and do not let the client clock grant eligibility.
- Keep internal avatar storage paths outside mass assignment and do not let secondary activity-log failure invalidate a mutation already committed successfully.

## Consequences

The Account hub remains compact while preserving existing destinations. Avatar data and referral eligibility stay attached to the shared mesale.vn user record. Production-engine concurrency, migration rehearsal, physical-device coverage, and store evidence remain required before release.

## Release Constraint

Passing local SQLite, export, native debug, and emulator checks does not authorize production migration/deployment or change the App Store and Google Play `NOT READY` verdict.
