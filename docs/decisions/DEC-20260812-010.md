# DEC-20260812-010 - Separate withdrawal history from request creation

- Date: 2026-08-12
- Session: `SES-20260812-014`
- Checkpoint: `CKP-20260812-020`
- Status: accepted for the current mobile batch

## Decision

- Keep withdrawal history at `/(tabs)/wallet/withdrawals`.
- Use the direct `/(tabs)/withdraw` tab for withdrawal creation so the `Rut tien` tab remains active.
- Reuse the canonical `wallet/withdrawals/create` component inside the direct tab wrapper.
- Route all user-facing withdrawal/create actions to the direct tab, while actions explicitly labelled as history remain on the history route.
- Back from the direct withdrawal tab opens history.

## Rationale

- This matches the two owner-provided Android references and removes the ambiguity between reviewing past requests and creating a new request.
- Reusing the create component preserves one API and business-logic implementation.
- The route model keeps Laravel authoritative for balances, payment accounts, OTP, validation, fees, minimums, idempotency, and withdrawal submission.

## Rejected Alternatives

- Redirecting the `Rut tien` tab into the wallet stack, which highlights the wrong bottom tab.
- Keeping all withdrawal-labelled actions on the history screen.
- Duplicating the create form or its API logic for the direct tab.
