# DEC-20260810-005 - Direct Tab Aliases for Nested Wallet Screens

- Date: 2026-08-10
- Session: `SES-20260810-004`
- Status: accepted for Round B

## Decision

Use direct `(tabs)/orders.tsx` and `(tabs)/withdraw.tsx` aliases that re-export the existing `wallet/orders` and `wallet/withdrawals` screen implementations. Keep the original nested wallet routes as the canonical deep-link destinations used by the More sheet.

## Rationale

Expo Router `5.1.11` resolves `Tabs.Screen` names against direct children of the current layout. A nested `wallet/orders` name is not a direct child while `wallet/_layout.tsx` owns the nested stack, so it cannot reliably become a top-level tab. A minimal alias preserves the existing screen implementation and avoids copying or rewriting wallet content.

## Consequences

- The four visible tabs render the exact existing Orders and Withdraw screen implementations.
- More-sheet links keep the website-compatible nested paths.
- Android back-stack behavior between an alias tab and a nested wallet deep link still requires physical-device verification before release.
