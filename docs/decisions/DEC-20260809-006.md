# DEC-20260809-006 - Restore Main Without Rewriting History

- Date: 2026-08-09
- Timezone: Asia/Bangkok
- Status: accepted and applied
- Session: `SES-20260809-002`

## Context

The remote `main` branch had been initialized with an empty root commit, while the reviewed migration baseline already existed at `6153a91`. Keeping the empty baseline would make the draft PR misleading and could complicate future history and comparisons. Recreating an orphan branch or force-pushing would risk rewriting shared history.

## Decision

Restore `main` with a normal merge commit that:

- preserves the exact tree from reviewed baseline `6153a91`;
- retains both the empty remote-main history and the migration history as parents;
- advances `origin/main` by fast-forward only;
- does not force-push, delete branches, or rewrite commits.

The resulting `main` commit is `6854dec`. The feature branch remains separate and draft PR #6 remains unmerged.

## Consequences

- `main` is no longer an empty/orphan review baseline.
- The PR has a meaningful repository baseline without losing either history.
- Documentation and PR rollback text must not claim that `main` is empty.
- Future work must merge/synchronize from restored `main` normally and must not recreate an orphan branch.
