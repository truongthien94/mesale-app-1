# DEC-20260815-005 - Keep Domain Statuses, Expose Mobile Claimability

- Date: 2026-08-15
- Session: `SES-20260815-005`
- Checkpoint: `CKP-20260815-005`
- Status: accepted for source implementation

## Decision

- Keep Laravel's existing `user_tasks.status=completed` domain value and map it to API `claimable` at the Open API boundary.
- Let the mobile client enable claim only when the server returns `claimable`; it must never infer claimability from progress or reward amount.
- Keep successful claim messaging tied to the integer `amount` returned by Laravel.

## Rationale

- This avoids a risky enum/database migration while making the API contract explicit for native clients.
- Server authority prevents locked milestones, duplicate claims, and client-side progress guesses from creating financial side effects.
- A shared hero component keeps the requested visual language consistent across light and dark screens.

## Rollout Note

- Production API rollout must be coordinated with the mobile release because older binaries may only recognize `completed`.
