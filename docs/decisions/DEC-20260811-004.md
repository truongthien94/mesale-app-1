# DEC-20260811-004 - Keep four Orders chips while showing unrecorded activity honestly

- Session: `SES-20260811-008`
- Task: `TSK-MOB-023`
- Status: accepted implementation decision

## Context

The approved Orders reference contains exactly four chips: all, pending confirmation, approved, and rejected. Laravel also has a feature-flagged unrecorded-click feed representing purchases that may not yet have been returned by the marketplace.

## Decision

- Keep exactly four visible status chips.
- Include unrecorded entries only in `Tất cả`, with explicit `Chờ sàn ghi nhận` and estimated-value copy.
- Keep pending, approved, and rejected chip queries server-side and recorded-order-specific.
- Return approved-order cashback as a dedicated integer VND summary field instead of deriving it from loaded pages or the broader lifetime cashback counter.
- Keep Bot API responses recorded-order-only.

## Consequences

The screen matches the approved chip hierarchy without hiding unrecorded activity or presenting it as a confirmed order. Users cannot isolate unrecorded entries with a dedicated fifth chip; adding one requires a future product decision.

## Release Constraint

This additive contract must be deployed through staging/security/monitoring gates. Local tests and emulator screenshots do not replace physical-device, signed-artifact, or store evidence.
