# DEC-20260810-004 - Round A Theme Compatibility Boundary

- Date: 2026-08-10
- Session: `SES-20260810-003`
- Status: accepted for Round A

## Decision

Use a provider-driven theme boundary with `system` as the first-launch preference and explicit `light`/`dark` overrides persisted in SecureStore. Keep the existing named `colors` export as an alias of `lightColors` until individual screens are migrated in later rounds.

## Rationale

The provider enables dark-mode behavior for future native screens without changing current visible layouts. The compatibility alias prevents an unscoped rewrite of existing consumers and preserves light-mode rendering in Round A. Icon packages are installed now for the planned native navigation/menu work but remain unused until the separately authorized UI rounds.

## Consequences

- Current screens continue to render their existing light tokens.
- New screens can consume `useTheme()` and switch between system and explicit schemes.
- A future screen-by-screen token migration is required before the app can claim complete dark-mode visual parity.
