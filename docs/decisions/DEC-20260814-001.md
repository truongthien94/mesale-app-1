# DEC-20260814-001 - Keep reward milestones server-authoritative

- Date: 2026-08-14
- Session: `SES-20260814-001`
- Checkpoint: `CKP-20260814-001`
- Status: accepted

## Decision

- Use the existing Laravel Tasks API as the only source for milestone targets, rewards, progress, status, and claim eligibility.
- Present `action=referral` tasks as the invite timeline and `action=cashback` tasks as the completed-order timeline.
- Do not hardcode the example targets or reward values in the mobile bundle.
- Keep Withdrawal routable from financial screens but remove it from primary tabs in favor of Tasks.

## Rationale

- Reward eligibility and wallet mutations must remain transactional and server-authoritative.
- Laravel Admin can change campaigns without shipping a new native binary.
- Hardcoded reward values could become misleading, conflict with production, or create an unsafe earnings claim.
