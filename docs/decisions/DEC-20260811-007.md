# DEC-20260811-007 - Keep member UI parity server-authoritative and native

- Session: `SES-20260811-011`
- Task: `TSK-MOB-026`
- Status: accepted implementation decision
- Source: `305838c`

## Context

The approved references contain example amounts, rates, rewards, account destinations, and withdrawal terms. Copying those examples into production UI would create fake financial claims and diverge from the shared mesale.vn account.

## Decision

- Rebuild the references as native React Native views, not WebViews.
- Read rewards, referral rates, counts, balances, minimums, fees, OTP policy, payment accounts, and histories from existing Laravel Open API contracts.
- Keep the 72-hour referral eligibility decision on Laravel and use server timestamps only for explanatory copy.
- Preserve idempotent financial submission and existing auth/throttle/logging boundaries.
- Treat dark mode, safe areas, and bounded navigation-header scaling as parity requirements, while allowing screen content to follow platform font scaling.
- Do not add store-link cards, sample member data, screenshot amounts, or backend/schema changes for this UI batch.

## Consequences

The screens follow the approved visual direction without creating a second business-data source or misleading financial values. Physical devices, signed builds, full accessibility matrices, and store evidence remain required before release.
