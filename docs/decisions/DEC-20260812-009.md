# DEC-20260812-009 - Server-backed native coupon and payment destination selection

- Date: 2026-08-12
- Session: `SES-20260812-013`
- Checkpoint: `CKP-20260812-019`
- Status: accepted for the current mobile batch

## Decision

- Use native searchable selection for payment destinations while preserving the Laravel allow-list as the only source of bank and wallet values.
- Use a dedicated native coupon route backed by the existing Laravel `/coupons` contract. Counts, categories, expiry, redirect links, and coupon codes are never invented in the mobile bundle.
- Keep referral eligibility and expiry server-authoritative. The client only routes and renders the flags returned by Laravel and never authorizes by local time.

## Rationale

- This matches the supplied mobile references without WebView and keeps financial/coupon mutations server-authoritative.
- Existing API contracts can support the requested screens without a database or production schema change.
- Native loading, empty, error, offline, retry, clipboard, and external-handoff states are reviewable on both platforms.

## Rejected Alternatives

- Hardcoded bank lists or coupon values.
- WebView/Blade route reuse.
- Client-clock referral authorization.
- A mobile-only database or production data copy.
